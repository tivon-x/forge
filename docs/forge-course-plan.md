# Forge 教学项目建设计划

## 1. 文档定位

本文档定义如何把 Forge 从一个主要由 Codex 代为实现的项目，转变为一个由学习者亲手完成、Codex 负责课程建设和教学支持的工程化教学项目。

本文档与 `docs/forge-implementation-plan.md` 分工如下：

- `forge-implementation-plan.md` 是产品路线，回答 Forge 最终需要具备什么能力。
- 本文档是教学路线和课程建设路线，回答学习者如何逐步掌握这些能力，以及 Codex 如何建设和维护这套教程。
- 当前代码和测试仍然是已实现行为的第一事实来源。课程内容与当前实现冲突时，必须明确指出差异，不能静默把计划当成现状。

本计划先固定课程目标、课程骨架、网站形态、练习与验收机制，以及后续各建设阶段中 Codex 的职责。具体页面文案、组件设计和练习代码在对应建设阶段中完成。

## 2. 转型目标

Forge 的核心目标不再只是“完成一个 coding agent”，而是让学习者最终能够独立做到：

- 使用 TypeScript 和 Node.js 实现可靠的异步系统。
- 解释 coding agent 的核心组成、数据流和边界。
- 独立实现 provider-neutral agent loop、工具调用闭环和流式事件。
- 正确处理取消、并发、异常、资源清理和协议不变量。
- 实现具备 cwd 边界、链接检查和保守编辑语义的 coding tools。
- 理解 provider adapter、session、项目上下文、CLI 和 renderer 的职责。
- 对多 provider、上下文压缩、skills、TUI、MCP、安全策略和 eval 形成系统认识。
- 在面试中解释关键决策、替代方案、失败路径和工程权衡。
- 面对新的 agent 需求时，能够自行分析和实现，而不是依赖既有答案。

最终交付物仍然是一个真实、可运行、可测试、可写入简历的 Forge CLI。教学网站不是替代品，而是完成 Forge 的学习入口。

## 3. 教学原则

### 3.1 真实工程优先

课程任务直接作用于真实 Forge 仓库，不在网页沙盒中实现简化版玩具 agent。每个核心任务都应产生可合并、可测试、可解释的工程成果。

小型隔离练习只用于学习 TypeScript、异步迭代器、取消等前置知识。掌握概念后必须回到真实 Forge 代码中应用。

### 3.2 学习者负责核心实现

默认协作边界：

- Codex 负责课程网站、课程内容、题目、starter、验收工具、测试、代码审查和分级提示。
- 学习者负责方案思考、生产代码、测试补充、问题修复和阶段答辩。
- Codex 默认不直接修改课程要求学习者实现的生产代码。
- 学习者明确要求“直接实现”时，Codex可以代为修改，但必须标记本次任务不再计入独立完成记录。
- 基础设施缺陷、课程错误和验收器错误由 Codex 直接修复，不转嫁给学习者。

### 3.3 先形成心智模型，再写代码

每个单元必须先解释问题、边界和数据流，再给任务。课程不能退化成逐行复制教程，也不能只给 API 用法而不解释设计原因。

### 3.4 提示逐级释放

每道核心任务最多提供三级提示：

1. 一级提示：指出需要检查的概念、约束或代码区域。
2. 二级提示：给出接口关系、状态转换或伪代码。
3. 三级提示：给出局部实现示例，但不直接提供整题答案。

完整参考实现不放在默认学习页面中。课程网站中的隐藏内容只用于降低干扰，不视为安全隔离。

### 3.5 验收不等于测试通过

课程完成度由四部分共同决定：

- 行为正确：公开测试和必要的补充验收测试通过。
- 架构正确：依赖方向、公共协议和第三方类型边界符合约束。
- 工程可靠：错误、取消、资源清理和边界条件得到处理。
- 能够解释：学习者完成设计说明、复盘和阶段答辩。

### 3.6 螺旋式学习

课程先尽快跑通一个最小纵向闭环，再逐轮增加可靠性和产品能力。不会在掌握 agent loop 之前堆积大量抽象，也不会把 TUI、MCP 等外围能力提前到核心协议之前。

## 4. 教学系统组成

完整教学项目由三个相互配合的部分组成：

```text
教学网站
  -> 讲解、任务、提示、进度、复盘和面试题

Forge 学习工作区
  -> 学习者实现真实生产代码和测试

课程验收器
  -> 执行自动检查并生成可理解的反馈
```

### 4.1 教学网站

网站负责：

- 展示完整学习路线和模块依赖。
- 提供统一格式的课程与任务页面。
- 保存本地学习进度。
- 按需展开提示、常见错误和复盘问题。
- 提供术语索引、架构说明和面试训练入口。
- 明确当前任务对应的仓库状态、文件范围和验收命令。

网站不负责：

- 在浏览器中模拟完整开发环境。
- 执行任意本地命令。
- 保存 API key 或其他凭证。
- 第一版提供账号、后端、云同步或多人班级管理。
- 把完整答案伪装成教程正文。

### 4.2 Forge 学习工作区

学习者在本地编辑真实仓库。课程建设阶段需要设计可恢复的 Git 学习基线，保留当前完整实现作为参考，不能通过删除历史或覆盖工作区来制造 starter。

具体分支和标签方案要在审计现有提交历史后确定，至少满足：

- 当前已实现版本可随时恢复和比较。
- 学习路径有明确的起点和阶段检查点。
- 课程网站和验收器可以在学习分支中正常运行。
- 进入下一阶段不依赖未完成的未来代码。
- 不要求学习者反复执行危险的历史改写命令。

### 4.3 课程验收器

课程应提供统一命令，目标用法类似：

```bash
pnpm lesson:list
pnpm lesson:check 03.04
pnpm lesson:check 03
```

具体命令名在实现阶段确认。验收器应复用 Vitest、TypeScript、Biome 和已有测试能力，不另造重量级任务框架。

验收结果至少区分：

- 前置状态不满足。
- 类型或构建失败。
- 行为测试失败。
- 架构约束失败。
- 需要人工审查或答辩。
- 课程基础设施自身发生错误。

验收器不得读取凭证、调用真实 provider 或访问网络。真实 OpenAI 继续只通过显式 smoke test 验证。

## 5. 网站信息架构

第一版使用内容优先的静态文档站。推荐采用 VitePress，并保持在现有单 package 中，不为课程网站引入独立 monorepo package。

建议目录：

```text
course/
  index.md
  getting-started/
  roadmap/
  foundations/
  agent-protocol/
  agent-runtime/
  coding-tools/
  providers/
  sessions-and-coding/
  cli-and-renderers/
  configuration/
  context-and-extensions/
  advanced-product/
  reliability-and-capstone/
  reference/
  .vitepress/
    config.ts
    theme/
    components/
```

主要页面类型：

- 首页：项目目标、适合人群、学习方式和继续学习入口。
- 路线图：模块关系、必修与选修、阶段成果。
- 模块首页：学习目标、前置模块、任务列表和阶段验收。
- 课程页：概念讲解、示例、思考题和关联任务。
- 任务页：需求、约束、修改范围、提示和验收。
- 里程碑页：端到端验收、演示任务、复盘和答辩。
- 架构参考：核心数据流、模块边界和协议不变量。
- 术语表：agent、turn、message、event、tool call、provider 等术语。
- 面试训练：按主题组织的解释题、设计题和故障分析题。
- 故障排查：课程环境、测试和常见实现错误。

第一版交互组件控制在必要范围内：

- `CourseProgress`：显示模块和课程完成度。
- `LessonChecklist`：保存阅读、实现、验收和复盘状态。
- `HintPanel`：逐级释放提示并记录已使用级别。
- `TaskCard`：统一展示任务范围、约束和命令。
- `QuizBlock`：提供无需后端的概念自测。
- `MilestoneStatus`：汇总阶段检查项和人工答辩状态。
- `Callout`：区分原理、风险、常见错误和面试重点。

进度第一版保存在浏览器 `localStorage`。课程内容本身必须在没有 JavaScript 进度功能时仍可正常阅读。

## 6. 单节课程规范

每节课程必须包含以下字段或章节：

1. 课程编号和标题。
2. 所属模块与前置课程。
3. 本节为什么存在。
4. 可验证的学习目标。
5. 必要概念和最小示例。
6. 与 Forge 架构的关系。
7. 编程任务或分析任务。
8. 明确的文件范围和禁止事项。
9. 公开验收命令与通过标准。
10. 三级提示。
11. 常见错误及其根因。
12. 完成后的复盘问题。
13. 对应面试问题。
14. 下一节入口。

任务描述必须满足：

- 不依赖未讲解的未来模块。
- 不要求猜测隐藏接口。
- 不通过含糊措辞规定关键行为。
- 明确哪些现有 helper 必须复用。
- 明确取消、错误和边界条件是否属于本题范围。
- 验收命令真实存在，且在指定起始状态下能够执行。

## 7. 完整课程骨架

课程分为必修主线、进阶主线和选修专题。编号是课程稳定标识，后续可以增补小节，但不应随意重排已发布编号。

### 模块 00：开始之前

目标：理解学习方式，建立可恢复的开发环境，并对当前能力形成基线。

- `00.01` Forge 要解决的根本问题。
- `00.02` Chat CLI、agent 与 coding agent 的区别。
- `00.03` 仓库地图、架构边界和事实来源。
- `00.04` Node.js、pnpm、TypeScript、Vitest 和 Biome 环境检查。
- `00.05` Git 学习基线、检查点和参考实现使用规则。
- `00.06` 入门能力诊断与第一次架构表达。
- `00.M` 里程碑：能够从用户输入讲清 Forge 的完整数据流。

### 模块 01：TypeScript 与异步基础

目标：掌握实现 agent runtime 必需的 TypeScript 和异步机制。

- `01.01` strict TypeScript 与“不可信输入”。
- `01.02` discriminated union 与穷尽检查。
- `01.03` 泛型、接口和依赖注入。
- `01.04` ESM、NodeNext 和 `.js` 相对导入。
- `01.05` Promise、异步边界和错误传播。
- `01.06` `AsyncIterable` 与 `AsyncGenerator`。
- `01.07` `AbortController`、`AbortSignal` 和取消竞态。
- `01.08` Zod schema 与类型推导。
- `01.09` Vitest、fake、stub 与确定性测试。
- `01.M` 里程碑：实现一个可流式输出、可取消、可测试的小型异步管线。

### 模块 02：Agent 公共协议

目标：从边界出发定义 provider-neutral 的核心语言。

- `02.01` 先定义协议而不是先写 loop。
- `02.02` user、assistant 和 tool message。
- `02.03` assistant text、tool calls 和 provider metadata。
- `02.04` AgentEvent 与事件作为系统边界。
- `02.05` ToolDefinition、schema、context 和结构化结果。
- `02.06` ModelProvider 与 provider event。
- `02.07` Forge 公共错误和稳定错误码。
- `02.08` 模块依赖方向与第三方类型隔离。
- `02.09` 协议 contract tests。
- `02.M` 里程碑：使用 fake provider 描述一轮完整响应，但暂不执行工具。

### 模块 03：Agent Loop 与 Harness

目标：实现 coding agent 的核心状态机和运行约束。

- `03.01` 最小无工具 agent loop。
- `03.02` 文本流和 message 生命周期。
- `03.03` 单个 tool call 闭环。
- `03.04` 多工具调用与结果配对。
- `03.05` 多轮模型调用和最终答案。
- `03.06` 未知工具、schema 错误和执行错误。
- `03.07` max turns 与无限循环保护。
- `03.08` provider 失败、流提前结束和 `response_end` 不变量。
- `03.09` 取消期间的消息一致性与资源清理。
- `03.10` AgentHarness 和单 prompt 并发限制。
- `03.11` queued steering 与 follow-up 的概念设计。
- `03.M` 里程碑：通过 fake provider 完成无工具、单工具、多工具、失败和取消场景。

### 模块 04：Coding Tools 与文件安全

目标：理解 coding agent 能力和风险主要来自工具，而不是 prompt。

- `04.01` Tool execution context 和 cwd 能力边界。
- `04.02` lexical path 检查与路径规范化。
- `04.03` realpath 检查、目录链接和 TOCTOU 风险。
- `04.04` `readFile`、编码、大小限制和截断。
- `04.05` `safeWriteText`、最终 symlink 和安全写入。
- `04.06` `writeFile` 的新建与覆盖语义。
- `04.07` `editFile` 的唯一精确替换。
- `04.08` `child_process.spawn` 与 shell 退出语义。
- `04.09` shell 取消、超时和子进程清理。
- `04.10` stdout/stderr、尾部诊断和字节级截断。
- `04.11` 工具错误如何安全地返回模型上下文。
- `04.M` 里程碑：让 fake agent 安全地读取、修改文件并运行测试。

### 模块 05：真实 Provider Adapter

目标：把第三方模型 SDK 限制在 provider 边界，并正确处理流事件。

- `05.01` provider adapter 的唯一职责。
- `05.02` Forge message 到第三方请求的映射。
- `05.03` OpenAI Responses API 的流式响应模型。
- `05.04` text delta、thinking 和 message 生命周期映射。
- `05.05` 增量 tool arguments 与 tool call 完成。
- `05.06` 成功流只能产生一次 `response_end`。
- `05.07` provider error、取消和不完整响应。
- `05.08` provider-specific opaque metadata。
- `05.09` adapter fake tests 与确定性事件序列。
- `05.10` 显式真实 OpenAI smoke test。
- `05.M` 里程碑：使用真实 provider 完成一次受控的文件读取任务。

### 模块 06：Session 与 CodingSession

目标：把无状态 agent runtime 组织成可持续使用的 coding session。

- `06.01` append-only JSONL 的适用边界。
- `06.02` session entry 与版本兼容思路。
- `06.03` 原子追加、读取和损坏记录处理。
- `06.04` in-memory storage 与存储 contract tests。
- `06.05` session replay 与消息恢复。
- `06.06` 项目级 session index。
- `06.07` CodingSession 的职责和依赖注入。
- `06.08` prompt、terminal shortcut 与并发互斥。
- `06.09` system prompt builder。
- `06.10` AGENTS.md 发现、顺序、大小和 symlink 约束。
- `06.11` 本地命令为什么不进入 agent loop。
- `06.M` 里程碑：恢复历史会话并在相同项目上下文中继续运行。

### 模块 07：CLI、Renderer 与交互协议

目标：让不同 UI 只消费结构化结果和 AgentEvent。

- `07.01` CLI 参数解析和 executable entry point。
- `07.02` one-shot print mode。
- `07.03` text renderer 的最终输出语义。
- `07.04` JSON Lines event renderer。
- `07.05` transcript renderer 和工具状态。
- `07.06` stdout、stderr 与退出码分离。
- `07.07` 最小行式交互终端。
- `07.08` slash command registry。
- `07.09` `!cmd` 与 `!!cmd` 的上下文语义。
- `07.10` `/clear`、`/resume` 和 session 切换。
- `07.M` 里程碑：完成可脚本调用、可恢复、可交互的 Forge CLI。

### 模块 08：配置、多 Provider 与模型切换

目标：在不污染 agent core 的前提下支持真实配置和多个模型平台。

- `08.01` 配置来源、优先级和稳定错误。
- `08.02` JSONC 解析与 Zod 校验。
- `08.03` API key 环境变量和凭证边界。
- `08.04` provider catalog。
- `08.05` model selection 与 session model entry。
- `08.06` OpenAI-compatible adapter。
- `08.07` Anthropic adapter 的协议差异。
- `08.08` provider retry envelope。
- `08.09` thinking/reasoning 配置隔离。
- `08.M` 里程碑：不改源码即可配置 provider、选择模型并恢复会话。

### 模块 09：上下文、Skills 与 Prompt Templates

目标：理解长会话管理和文件驱动扩展能力。

- `09.01` token 估算的目标和精度边界。
- `09.02` context usage 的组成。
- `09.03` compaction entry 与不可变历史。
- `09.04` summary 结构、最近消息保留和信息丢失风险。
- `09.05` 自动压缩阈值和取消。
- `09.06` skills discovery 与调用规则。
- `09.07` prompt templates discovery。
- `09.08` reload 与缓存失效。
- `09.M` 里程碑：长会话可压缩，新增 skill 和 prompt 后可重新加载。

### 模块 10：交互体验与高级 Session

目标：在稳定事件协议之上构建更好的使用体验。

- `10.01` TUI 是事件消费者，不是 agent runtime。
- `10.02` streaming message view 与渲染状态。
- `10.03` tool call 展开、折叠和 thinking 展示。
- `10.04` 输入、快捷键和命令补全。
- `10.05` 取消、queued steering 和 queued follow-up。
- `10.06` session parent、leaf 和树结构。
- `10.07` 从历史消息创建分支。
- `10.08` Markdown、HTML 和 JSONL export。
- `10.M` 里程碑：在 TUI 中完成长任务、中断、恢复和分支。

### 模块 11：安全、MCP、Eval 与发布

目标：把能用的 agent 推进到边界清晰、可诊断、可扩展的工程产品。

- `11.01` 当前 shell 能力为什么不是 sandbox。
- `11.02` command approval policy。
- `11.03` destructive command 与 file write scope policy。
- `11.04` tool registry 和 custom tool source。
- `11.05` MCP client、transport 和 tool mapping。
- `11.06` MCP resources 与 prompts。
- `11.07` per-tool timeout 与 permission policy。
- `11.08` diagnostic logging 和敏感信息脱敏。
- `11.09` structured error classification。
- `11.10` benchmark、eval dataset 和回归门禁。
- `11.11` Windows、macOS 和 Linux 行为差异。
- `11.12` build、package、release 和公开文档。
- `11.M` 最终项目：从需求出发扩展 Forge，并完成设计说明、测试、演示和答辩。

## 8. 课程主线与产品 Phase 映射

| 产品实施阶段 | 主要课程模块 | 说明 |
|---|---|---|
| Phase 1 | 01、02、03、04、05、07 的前半 | 产品 Phase 1 对初学者跨度过大，课程必须拆开 |
| Phase 2 | 06、07 | 先理解存储协议，再处理 renderer 和 resume |
| Phase 3 | 06、07 | 项目上下文、本地命令和交互终端归入 coding 应用层 |
| Phase 4 | 08 | 配置、凭证和 provider 差异集中学习 |
| Phase 5 | 09 | context、compaction 和文件驱动扩展 |
| Phase 6 | 10 | TUI 建立在稳定事件协议之上 |
| Phase 7 | 10 | session tree 与 export |
| Phase 8 | 11 | MCP 作为 tool source，而不是 agent dependency |
| Phase 9 | 04、11 | 文件安全从早期开始，完整 approval 和诊断后置 |
| Phase 10 | 11 和专题项目 | 差异化能力通过 capstone 和选修扩展 |

## 9. 学习评价与面试训练

每节任务记录四类状态：

- `read`：完成概念学习和自测。
- `implemented`：完成学习者负责的代码。
- `verified`：自动验收通过。
- `explained`：完成复盘或答辩。

每个里程碑至少包含：

- 一个端到端演示任务。
- 一次不看代码的架构讲解。
- 一道故障定位题。
- 一道替代方案比较题。
- 一次代码审查和修改。
- 一份简短的学习记录，说明做过的关键决策和犯过的错误。

面试题不以背诵定义为主，应重点检查：

- 为什么选择这种边界。
- 如果不这样设计会发生什么。
- 哪些不变量由哪个模块保证。
- 取消或失败发生在异步边界中间时如何收尾。
- 如何用测试证明行为而不是证明实现细节。
- 面对新 provider、新工具或新 UI 时应该改哪里。

## 10. Codex 建设阶段

以下阶段描述的是“Codex 如何实现教程”，不是学习者实现 Forge 的课程顺序。每一阶段都必须独立可验证、可回滚，不能依赖下一阶段才能成立。

### 建设阶段 A：课程事实审计与基线设计

Codex 负责：

- 读取当前代码、测试、提交历史、产品计划和 smoke test。
- 建立“当前已实现能力—课程模块—产品 Phase”清单。
- 识别当前实现中适合作为参考的部分和需要学习者重新实现的核心部分。
- 提出可恢复的 Git 参考版本、starter 和检查点方案。
- 明确哪些任务使用隔离练习，哪些任务直接修改 Forge。
- 记录计划与当前行为之间的具体冲突。

Codex 不负责：

- 删除当前实现以制造空白项目。
- 未经确认创建或改写大量分支和标签。
- 在审计完成前假设当前代码已经覆盖完整 Phase。

交付物：

- 课程能力审计文档。
- 课程状态与产品状态映射。
- Git 学习基线方案。
- 第一批任务的前置状态说明。

验收：所有结论能指向真实代码、测试或文档；工作区不丢失现有成果。

### 建设阶段 B：网站基础设施

Codex 负责：

- 在现有单 package 中接入固定版本的 VitePress。
- 创建 `course/` 目录、站点配置、导航、侧栏和基础主题。
- 增加开发、构建和预览命令。
- 配置本地搜索、代码高亮、静态资源和链接检查基础。
- 创建首页、路线图、模块占位页和贡献说明。
- 确保网站产物、缓存和临时文件不会提交。

Codex 不负责：

- 引入账号系统、数据库、CMS 或独立后端。
- 为展示效果引入与教学无关的复杂动画和前端状态框架。
- 改变 Forge CLI 的运行时依赖边界。

验收：课程站点可本地开发、静态构建和预览；`pnpm verify` 继续通过。

### 建设阶段 C：课程内容模型与交互组件

Codex 负责：

- 定义课程编号、frontmatter 和页面模板。
- 实现进度、清单、提示、任务、自测和里程碑组件。
- 使用 `localStorage` 保存个人进度，并处理 schema 版本升级。
- 保证页面在无进度数据、损坏数据和禁用客户端脚本时仍可阅读。
- 建立课程写作规范和内容检查规则。
- 为所有模块生成符合统一结构的骨架页面。

Codex 不负责：

- 用前端隐藏代替答案隔离策略。
- 收集个人信息或把进度上传到外部服务。
- 在课程 metadata 中复制一份与正文容易漂移的完整事实源。

验收：任一新课程可以按模板添加；导航、进度和提示行为有自动测试或稳定的人工验收步骤。

### 建设阶段 D：验收器与练习工作流

Codex 负责：

- 定义 lesson manifest 和验收结果 schema。
- 实现课程列表、单课检查和模块检查命令。
- 复用现有 TypeScript、Vitest、Biome 和 build 门禁。
- 为架构边界增加最小、稳定、可理解的检查。
- 区分学习者代码失败和课程基础设施失败。
- 编写 starter 状态检查，避免在错误版本上执行任务。
- 为人工答辩保留明确状态，不伪造自动判定。

Codex 不负责：

- 编写依赖精确源码文本或私有实现细节的脆弱检查。
- 通过网络或真实 API key 验收普通课程。
- 为了隐藏测试而引入独立服务。

验收：示例课程能够经历失败、获得可读反馈、修复并通过；错误不会破坏仓库内容。

### 建设阶段 E：基础与 Agent Core 课程

覆盖模块：00、01、02、03。

Codex 负责：

- 完成概念讲解、最小示例、任务、三级提示和常见错误。
- 编写异步管线、协议和 fake provider 练习。
- 为 agent loop 的文本、工具、失败、取消和并发场景提供验收。
- 将协议不变量与现有架构约束对应起来。
- 设计模块答辩题和故障定位题。
- 根据学习者真实使用反馈调整粒度和难度。

Codex 不负责：

- 默认替学习者实现 message、event、tool、provider、loop 或 harness。
- 只解释现有代码而不给独立设计空间。

验收：学习者可以不依赖真实 provider 完成最小 agent core，并解释关键状态转换。

### 建设阶段 F：Coding Agent 工程主线课程

覆盖模块：04、05、06、07。

Codex 负责：

- 完成 coding tools、安全边界、provider、session、CodingSession、CLI 和 renderer 课程。
- 为路径、symlink、取消、超时、截断和精确编辑准备可复现练习。
- 为 provider adapter 提供 fake stream 和 mapping 测试。
- 为 JSONL replay、项目指令和 CLI 输出语义提供验收。
- 组织多个纵向里程碑，保证每个阶段都有可运行 Forge。

Codex 不负责：

- 在普通验收中读取 `.env` 或运行真实模型。
- 把 shell 描述成完整 sandbox。
- 为降低难度而放宽现有安全约束。

验收：学习者可以构建可读取、修改、执行测试、记录会话并恢复的真实 Forge CLI。

### 建设阶段 G：进阶产品课程

覆盖模块：08、09、10。

Codex 负责：

- 完成配置、多 provider、上下文、skills、TUI 和 session tree 课程。
- 将必修主线与选修专题明确分开。
- 为 provider 差异、compaction 信息损失、TUI 状态和 session branching 设计专项练习。
- 防止进阶模块反向污染已稳定的 agent 协议。

Codex 不负责：

- 为追求课程数量提前实现尚未批准的产品功能。
- 把特定 UI 框架类型暴露到 agent 或 coding 公共协议。

验收：每个进阶模块可独立学习和合并；跳过选修不影响主线 Forge 成立。

### 建设阶段 H：安全、生态与最终项目

覆盖模块：11。

Codex 负责：

- 完成 approval、MCP、诊断、eval、跨平台和发布课程。
- 明确 Phase 9 前后的安全能力差异。
- 提供不依赖网络的 MCP fake 或本地测试环境。
- 设计最终 capstone 的选题、范围、评分 rubric 和答辩流程。
- 生成简历描述素材时只使用学习者实际完成且能够解释的内容。

Codex 不负责：

- 把缺失的操作系统隔离能力包装成安全保证。
- 替学习者选择并实现整个最终项目。
- 根据代码数量或页面勾选自动宣称“掌握”。

验收：学习者能够独立扩展一个 Forge 能力，并提供设计、实现、测试、演示和复盘证据。

### 建设阶段 I：全站质量、发布与持续维护

Codex 负责：

- 检查所有内部链接、命令、代码示例和前置关系。
- 完成桌面和移动端的阅读体验检查。
- 验证站点静态构建和部署流程。
- 对课程执行一次从 starter 到里程碑的完整 dry run。
- 建立课程版本、变更记录和迁移说明。
- 当 Forge 协议变化时同步检查受影响课程和验收器。

Codex 不负责：

- 在未完整走通课程前宣称教程完成。
- 把临时调试记录写入长期课程正文。
- 因网站发布而自动 push、创建远程仓库或修改发布目标。

验收：全站构建通过，核心课程实际可走通，部署行为获得用户明确授权。

## 11. 建设顺序与阶段门禁

推荐实施顺序：

1. A：先确认事实和学习基线。
2. B：建立最小可读网站。
3. C：固定课程格式和必要交互。
4. D：建立反馈闭环。
5. E：完成第一条可实际学习的主线。
6. 根据真实学习反馈修订 B、C、D。
7. F：完成简历项目最重要的工程主线。
8. G：按需要扩展产品能力。
9. H：完成可靠性、生态和最终项目。
10. I：全站验证和发布。

阶段 E 完成前，不大规模撰写进阶课程正文。可以预先保留完整骨架，但不能用低质量占位内容制造“整套课程已经完成”的假象。

每个建设阶段结束时必须：

- 运行与改动风险匹配的测试。
- 运行 `pnpm verify`。
- 网站相关阶段运行课程站点 build。
- 更新课程建设状态。
- 报告尚未实际走通的内容。
- 保持提交范围单一且可回滚。

## 12. 内容质量标准

课程内容必须满足：

- 技术事实来自当前代码、测试、正式文档或明确引用的外部一手资料。
- 示例代码足够小，只演示当前概念。
- 解释设计原因，不把现有实现描述成唯一答案。
- 关键术语首次出现时给出定义。
- 每个任务都能说明它对最终 Forge 的贡献。
- 每个公开命令都经过实际验证。
- 常见错误解释根因，不只给修复步骤。
- 不读取或展示 API key、token、`.env` 或 credentials。
- 不鼓励危险 Git 命令或不可恢复的学习流程。
- 文案对学习者直接、具体，不用空泛鼓励代替反馈。

## 13. 主要风险与处理

### 风险 1：教程网站反客为主

处理：坚持静态内容站和少量组件，不做通用学习平台。网站开发服务于 Forge 学习，不扩展成独立产品。

### 风险 2：课程变成被动阅读

处理：核心概念后立即安排真实任务；模块完成必须包含实现、验收和解释，不能只靠阅读进度。

### 风险 3：学习者照抄当前实现

处理：保留参考版本但不放入默认路径；题目强调行为和约束，允许不同实现；答辩检查真实理解。

### 风险 4：整套课程一次性生成导致内容空泛

处理：先固定完整骨架，再分批完成正文；第一批课程经过真实学习后再扩展后续模块。

### 风险 5：课程与代码持续漂移

处理：课程任务绑定稳定编号、前置状态和验收命令；协议变更时同时检查课程影响；避免在多处复制事实。

### 风险 6：隐藏测试鼓励猜题

处理：公开关键行为和架构约束；隐藏检查只覆盖已明确说明的要求，不加入未告知规则。

### 风险 7：Codex 再次承担核心实现

处理：默认教学契约明确区分课程基础设施和学习者生产代码；每次直接代写都显式记录，不计入独立完成。

### 风险 8：课程规模超过实际需要

处理：模块 00 至 07 构成简历项目必修主线；08 至 11 可按求职目标和时间选择。完整骨架不等于所有内容必须同时完成。

## 14. 第一版完成定义

教学项目的第一版不是“所有模块都有页面”，而是满足以下条件：

- 网站首页、路线图、模块导航和本地搜索可用。
- 课程进度、任务、提示和里程碑组件可用。
- 模块 00 至 03 内容完整并经过实际学习流程验证。
- 存在统一课程验收命令。
- 学习者能够从 starter 完成最小 agent core。
- 每个已发布任务都有真实验收、常见错误和答辩题。
- 网站和 Forge 默认门禁同时通过。
- 未完成模块明确标记为规划中，不使用空泛正文充数。

完成第一版后，再以模块 04 至 07 为第二个主要版本。做到这里，课程已经能够支撑一个有说服力的 coding agent 简历项目。模块 08 至 11 作为后续进阶版本建设。

## 15. 下一步

下一阶段应执行“建设阶段 A：课程事实审计与基线设计”，而不是立即开始美化网站或批量生成课程正文。

阶段 A 完成并确认后，再开始接入 VitePress。这样可以保证课程页面、starter、测试和当前仓库状态使用同一套真实边界，避免网站完成后才发现学习路径无法落地。
